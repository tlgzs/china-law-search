## 1. 九条对照表

编号、判据、失败文案、拦截位置、默认动作。失败文案是 `tools/release_gate.py` 里 `GATES` 常量的原文，CI 可直接按字符串匹配。

| 编号 | 名称 | 机器判据（可复现的 SQL/规则） | 失败文案 | 拦截位置 | 默认动作 |
|---|---|---|---|---|---|
| **G1** | 施行日↔效力双向一致 | ① `status='pending'` 且 `effective_date` 为空或 `<= today`；② `status='effective'` 且 `effective_date > today`。任一命中即失败 | 存在效力状态与施行日矛盾的版本：pending 却已到/已过施行日，或 effective 却是未来施行日 | 打包前 preflight | 阻断 |
| **G2** | 同名唯一现行 | 按 `norm_name` 分组，`status='effective'` 版本数 > 1 | 同一法规存在多个现行有效版本，检索会取到不确定的一版 | 打包前 preflight | 阻断 |
| **G3** | 生效区间不重叠 | 同法版本按 `publish_date` 升序后，相邻两版 `effective_date` **倒挂**（后者早于前者），或两版 `effective_date` **同日** | 同一法规的版本施行区间倒挂、重叠或同日生效，按时间点选版会选错 | 打包前 preflight | 阻断 |
| **G4** | 页尾/域代码残渣 | ① 11 条 Word 域代码正则（`PAGE\s*\\?\*\s*MERGEFORMAT`、`\\\*\s*MERGEFORMAT`、`HYPERLINK`、`SHAPE\s+\\\*`、`EMBED`、`NUMPAGES`、`SECTIONPAGES`、`PAGEREF`、`MERGEFIELD`、`\\l "_Toc"`、`TOC\s+\\o`）命中正文（按行去重计数）；② 末 200 字命中页脚 CTA 词（`扫一扫`/`手机阅读`/`责任编辑`/`扫描二维码`/`关注公众号`）；③ 末行 `2–40` 字且带站点特征且被 `≥10` 部法共用（告警） | 正文残留 Word 域代码或页脚 CTA，用户会看到「PAGE * MERGEFORMAT」这类垃圾 | 打包前 preflight | 阻断（重复尾行/`二维码`为告警） |

| **G7** | 条文切分异常 | ① `law_versions.article_count = 0`；② 条号重复（`(version_id, num, suffix)` 计数 > 1）；③ 单条 `LENGTH(content) > 5000`（排除 `law_type='amendment'`）；④ 跳号率 `1 - 实际条数/MAX(条号) > 5%`（排除 `amendment`/`other`） | 条文切分异常：0 条、跳号率超 5%、单条超 5000 字或条号重复 | 打包前 preflight | 阻断 |

### 退出码

| 退出码 | 含义 |
|---|---|
| `0` | 无阻断项（告警项不影响） |
| `1` | 存在阻断项 |
| `2` | 参数错误 / 库或 manifest 读取失败 |

`--strict` 时告警也计入失败（CI 想全绿时用）。

### 两个现存缺口如何被拦下

1. **「改库后没有 bump → 重打包 → 校验 manifest 的强制链」** → G8：库哈希与 manifest 不符、库 `corpus_version` 与 manifest 不符，两项任一命中即 `exit 1`；配 `--previous-manifest` 还能识别「库内容变了但没换 corpus_version」。
2. **`VERSION=2.3.5` 与 `manifest.app_version=2.3.3` 不一致** → G8 第 ② 项，实测输出：
   `VERSION(2.3.5) 与 manifest.app_version(2.3.3) 不一致 —— 打包后升了程序版本却没重打包`。

## 5. 判据偏离与废弃记录（正式口径）

本节是**正式判据**，凡与勘察报告 §B2 三冲突，以本节为准；原判据标注「已废弃」并写明原因。

### G3 生效区间不重叠

| | 内容 |
|---|---|
| **现行判据** | 同 `norm_name` 的版本按 `publish_date` 升序，相邻两版满足任一即阻断：① `effective_date` 倒挂（后公布版的施行日早于前版）；② 两版 `effective_date` 同日。`superseded_at` **只作信息项**输出，不参与判定。 |
| **已废弃判据** | 报告原文「相邻版本的失效日（`superseded_at`）不得早于下一版施行日」。 |
| **废弃原因** | 实测 252 个非空 `superseded_at` 中 **208 个是执行时间戳**（`2026-11-03T02:12:00Z`、`2026-11-03 02:11:44`），是入库/替代动作的执行时刻，不是法律失效日；能配到下一版施行日的 208 对里**208 对全部不一致**。照报告判据执行等于把数据全判成错。 |
| **重要口径（防误修）** | 命中不必然等于数据错误。典型形态是**合法重发版**：2026-09-19 重新发布的修正汇编版，正文沿用原施行日（如 2009-01-01）。这种版本在库里 `publish_date` 新、`effective_date` 老，会触发本条。**处理方式是人工确认该版本是否为官方重发/汇编版，确认后保留或调整 `effective_date`；不得因此删除版本或改写成新版施行日**——那会把合法重发版改坏。真实库 37 处倒挂均属此类，待人工逐条确认。 |

### G4 页尾 / 域代码残渣

| | 内容 |
|---|---|
| **现行判据** | ① 11 条 Word 域代码正则命中正文（按行去重，阻断）；② 末 200 字命中页脚 CTA（`扫一扫`/`手机阅读`/`责任编辑`/`扫描二维码`/`关注公众号`，阻断）；③ 末行 2–40 字 **且** 命中站点/版权/扫码特征（`https?://`、`www.`、`版权所有`、`Copyright`、`©`、`扫码`、`扫一扫`、`手机阅读`、`关注`、`公众号`、`责任编辑`、`来源:`、`PAGE`、`MERGEFORMAT`、`二维码`、`法律咨询`、`热线`），且被 ≥10 部法共用 → **告警**。 |
| **已废弃判据** | 报告原文「重复尾行 ≥10 部即残渣」（无前置条件）。 |
| **废弃原因** | 无前置条件时命中 **847 行**，绝大多数是「本条例自公布之日起施行。」「本法自 2020 年 1 月 1 日起施行。」这类**合法条文**——全库大量法规共用同一句施行条款。若照报告直接阻断，会把正常法规全部拦下。加站点/版权/扫码特征前置条件后，真实库降到 **75 行**，且降为告警；只有域代码与 CTA 阻断。 |
| **反例（看起来像但不是残渣）** | 「本条例自公布之日起施行。」「本法自 2021 年 1 月 1 日起施行。」「（2023 年 9 月 28 日通过）」——不含站点/版权/扫码特征，不计数。 |

### G6 同文重复

| | 内容 |
|---|---|
| **现行判据** | 同一 `norm_name` 不同版本的 `content_hash` 序列**完全相同** → **告警，不阻断**。 |
| **理由** | 真实库 19 对同文。「重新公布」是合法立法动作：法规被整体重新发布、条文逐字未变，版本号与公布日却应更新。这类同文版本是**正确数据**，阻断会逼着人去伪造差异。告警让发布者人工确认"这是重新公布还是重复转换件"；只有确认是转换错误才回退。 |

### G7 条文切分异常

| | 内容 |
|---|---|
| **现行判据** | ① `article_count = 0`；② 条号重复；③ 单条 `LENGTH(content) > 5000`（排除 `amendment`）；④ 跳号率 `1 − 实际条数/MAX(article_number_num) > 5%`（排除 `amendment` 与 `other`）。任一命中即阻断。 |
| **报告未写、本轮补充** | 跳号率排除 `law_type ∈ {amendment, other}`。 |
| **补充原因** | 修改/废止决定类文件的"条"是决定事项条目，本身就不按连续条号编排（常见只有 1–2 条，却挂着"第三百四十四条"这类被修改条号）；不排除会产生整批假阳性，把合法的修改决定全部判成切分错误。排除后真实库仍有 **226 部**跳号率超阈值，是真实的切分问题，保留阻断。 |

### G5 缺收录

| | 内容 |
|---|---|
| **现行判据** | ① 清单 `catalog.csv`（列 `norm_name,latest_publish_date`）内的法规未入库，或库内 `MAX(publish_date)` 落后；② `*.plan.json` 里 `summary.new_laws == 0 且 skipped_laws > 0`。 |
| **未给清单时** | 清单比对 **SKIP**（不是 FAIL）。 |
| **不硬编码假清单的原因** | 「应收录全集」在库内不存在：`reports/*.plan.json` 记的是**已处理**文件，不是应处理全集；`地方法规_markdown` 的 516 个未入库 md 里混有重复件与非法规文件，未经判定不能当清单。硬编码一份清单等于用自己编的标准判自己，门禁会变成橡皮章。 |
| **启用条件** | **需要数据侧产出 `reports/catalog.csv`**。文件一出现，`make_release.py` 自动启用清单比对（无需改代码）；也可显式 `--catalog`。 |

## 6. 使用方式

```bash
# 正常打包：门禁自动执行，无需额外参数
python3 tools/make_release.py --db data/law_data.db --out-dir dist

# 独立预检（发布前自检，无网络、只读、仅本地库文件）
python3 tools/release_gate.py \
  --db data/law_data.db \
  --manifest dist/manifest.json \
  --artifacts-dir dist \
  --version-file VERSION \
  --catalog reports/catalog.csv \
  --plans-dir reports \
  --previous-manifest dist/manifest.prev.json \
  --json reports/gate-report.json

# 只跑其中几条
python3 tools/release_gate.py --db data/law_data.db --only G1,G2,G3,G4,G7

# 结构性自检
python3 tools/release_gate_selftest.py
```

CI 可选启用：把上面的命令挂为 publish job 的前置步骤，非零退出即中止发布。`--json` 产物便于流水线解析。
