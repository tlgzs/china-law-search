# 数据 2026.11.03.3

> 发布时把本文件正文整段粘贴到 GitHub Release 正文。上方这一行 blockquote 可删。

条文截至 **2026-10-17**。库内 16,909 部法规，其中 16,830 部有现行有效版本，
另外 35 部是已公布、施行日未到的全新法，条文同样入库可检索；正文 700,378 条
（现行 698,728 条，已公布未生效 1,650 条），另存历史条文 340,231 条。

**库停在 2026.10.31.1 的，下几 MB 增量包即可，不必重新下全量。**

## 这一版主要修一件事：废止传不下去

上一版按废止决定标出了 44 部已终止的法规，但那个结果只对下全量包的人有效。
增量包的设计里没有「废止」这个概念——它逐部导出法规的现行版本与待生效版本，
一部法被废止后就一条现行版都不剩，打包时会被当成「库里没有这部法」跳过去。

结果就是：更新到上一版的增量用户，库里那 44 部法仍然标着现行有效，检索、核验、
复制条文都会照常给出，而它们实际已经失效。这比不更新更危险——不更新至少不知道自己缺，
照旧引用就会把已废止的条文写进文书。

所以本版给增量包加了独立的废止清单（格式升到 `schema 3`）：

- 打包端从全库扫出「一条现行版、一条待生效版都不剩」的法规，各写一条记录：
  名称、废止日期、依据的决定名称
- 记录里**不带正文**。接收端要做的是把本地那部法降级、条文标 `repealed`，
  一个字的正文都用不上。44 部合计 2,550 条正文若塞进去，增量包会从几 MB 涨到十几 MB
- 接收端本地没有这部法时直接跳过，不会凭空多出一部废法；本地早已标失效的也跳过，
  重复应用、断点重跑都不会重复处理

应用之后的行为：检索不再命中这部法，核验直接回「该法规已废止」并给出废止日期和依据决定，
`/api/law/article` 返回 `error=law_repealed`，不再给正文。

## 44 部法规按废止决定标为失效

从 76 条「关于废止……的决定」里解析出被废止的法规名，命中 44 部、1,823 条正文，
标 `repealed` 并记下废止日期与依据决定。

书名号会造成一个隐蔽的坑：决定名称写作「关于废止《海南省环境保护条例》的决定」，
被废止的那部法在库里的全称并不包含书名号，直接按字符串匹配连不上。本版改为先查决定名里
出现的书名号内文本，再反查库里的正式全称；反过来核验时，用户输入带不带书名号都能对上
（`resolve_law_names`）。

## 另外修的两处

**核验同名误判。** 上一版核验《海南省环境保护条例》会回「现行有效」——因为模糊匹配命中的是
那份废止决定的条文。改为精确同名优先：先按全称精确取，取不到再看这个名字是否只剩废止记录，
最后才模糊匹配。现在正确回「已废止」。

**修改决定的解析残留没清干净。** 上一版清了 228 条标注与 225 条标题残片，判定条件是
「首行是法规名的子串、且不短于 6 字」，6 字会漏掉只剩「的决定」这种短残尾。本版放宽到 3 字，
补清 6 条，目前残留为零。

## 怎么更新

三条路，判断逻辑一致，按习惯挑一个：

```bash
python3 tools/check_update.py --update    # 命令行：查 + 装
./update.sh                               # 同上，自带环境探测
```

macOS 也可以直接双击仓库里的 **`更新数据.command`**，跑完窗口会停住显示结果。

装了本地查询界面（`web/index.html`）的，页面顶部会出提示条，
点「立即更新」才装；点「×」记在浏览器本地，同一版本不再弹。

## 该下哪个包

| 你的情况 | 下这个 |
|---|---|
| 库是 2026.10.31.1 或更新 | `delta-2026.11.03.3.json.zst`（或 `.gz`） |
| 库更早，或第一次装 | `law_data-2026.11.03.3.db.zst`（或 `.gz`） |

`check_update.py` 会自己判断走哪条，不用手工挑。增量路径任何一步不通（格式不认、
解压失败、校验不过）都会自动回落到全量。

**注意：本版增量包是 `schema 3`，2.3.2 及更早的程序不认**，会提示改用全量包。
用 `git pull` 更新到 2.3.3 后再走增量。

手动应用增量包：

```bash
python3 tools/apply_delta.py --delta delta-2026.11.03.3.json.gz
```

跑完会打出自检结果，包含应用几部、废止几部。这个动作是幂等的：同一部法同一天同一版
已在库里就跳过，重复跑、断点重跑、换机器再跑，都只会补建索引，不会插出两份同样的版本。

## 程序版本

数据可以自动装，**程序不会自动更新**。本版对应的程序是 **2.3.3**（tag `app-v2.3.3`）：

```bash
git pull && ./update.sh
```

2.3.3 的改动就是这一版数据需要的：增量包的 `schema 3` 与废止清单、自检不再把废止报成
「无生效版本」、统计口径拆分。2.3.2 带来的是核验侧的修正——精确同名优先、`law_repealed`
错误码、修改决定残留补清。启动脚本同时支持 `.venv` 与 `venv` 两种目录名。

## 校验

五个文件，文件名必须与 `manifest.json` 的 `artifacts[].name` 逐字一致：

| 文件 | 内容 |
|---|---|
| `manifest.json` | 版本、条数、各资产 sha256 |
| `law_data-2026.11.03.3.db.zst` / `.gz` | 全量库 |
| `delta-2026.11.03.3.json.zst` / `.gz` | 增量包 |

`fetch_data.py` 与 `apply_delta.py` 都会校验 sha256，不用手工算。

manifest 里另带 `app_version: 2.3.3` 与 `schema_version: 3`，可与本地 `/health` 对照。

## 已知边界

- **废止的识别靠决定名称。** 笼统表述（「关于废止部分行政法规的决定」）、一条决定废止多部法
  而名称里又没有书名号的，目前跳过不处理，留给人工确认。44 部是能确定的那部分。
- **修改决定的正文只有决定条文本身**，不包含被修改法规的合并后全文。查具体条文请直接
  查被修改的那部法规，它的现行版已按修改决定更新。
- 少数早期入库的法规（33 条）正文末尾仍带原始来源网址（`http://law.npc.gov.cn/...`），
  属溯源信息，未改动。
- 正文来自国家法律法规数据库及其原始镜像，条文文字不改写、不补标点。发现错漏欢迎按
  `CONTRIBUTING.md` 提 issue，交原件即可。
